# 光语助手（LuminaAssist）实验报告

**报告人**：陈默  
**完成日期**：2026-07-24  
**所属项目**：LuminaAssist 端云双态多模态智能助理  

---

## 一、实验目的

本次实验旨在验证光语助手在鸿蒙端侧与 FastAPI 后端协同下的核心能力是否可用，重点确认：

1. 后端服务能否正常启动，并完成健康检查与 Agent 任务规划；  
2. 端侧 App 能否完成语音输入、视觉识别、药品信息播报等主路径；  
3. 端云双态策略（端侧分类优先、后端规划代理、失败 TTS 兜底）是否符合设计预期；  
4. 无障碍交互（大热区、语音反馈）在真机使用中是否可达。

---

## 三、实验内容与步骤

### 3.1 后端可用性

1. 进入 `backend/`，安装依赖并配置 `.env` 中的 `ALIYUN_API_KEY`；  
2. 执行 `python main.py` 启动服务；  
3. 访问 `GET /health`，确认 `status=ok` 且 `api_key_configured=true`；  
4. 调用 `POST /api/v1/agent/plan`，输入自然语言指令，检查返回的 `tasks` 与 `tts_message`。

### 3.2 端侧部署与联调

1. 用 DevEco 打开 `LuminaApp/`，配置 `local.properties` 与调试签名；  
2. 部署至设备后，在设置页填写后端地址（真机使用电脑局域网 IP）；  
3. 依次验证：文本指令 → 长按语音 → 短按视觉识别。

### 3.3 功能场景用例

对本系统统一设计了以下实验用例（与另一份报告用例编号一致）：

| 编号 | 场景 | 操作 / 输入 | 观察点 |
| --- | --- | --- | --- |
| E-01 | 健康检查 | 请求 `/health` | 返回 ok，Key 已配置 |
| E-02 | 任务规划 | 「帮我看看眼前是什么」 | 返回结构化 tasks + TTS 文案 |
| E-03 | 阅读辅助 | 「读一下说明书」+ 拍照 | 播报可读文字，无静默失败 |
| E-04 | 物体识别 | 「前面是什么」+ 拍照 | 有分类/描述结果；弱网可走端侧 |
| E-05 | 药品识别 | 「这是什么药」+ 药盒图 | 卡片字段与语音基本一致 |
| E-06 | 自由问答 | 「今天星期几」 | 有答复，错误有语音提示 |
| E-07 | 故障兜底 | 故意填错后端地址 | 网络失败可感知，不崩溃 |
| E-08 | 权限拒绝 | 拒绝相机后点识别 | 有提示，应用不退出 |

## 四、实验结果

| 编号 | 结果 | 简要说明 |
| --- | --- | --- |
| E-01 | 通过 | 后端日志可见 Key 已配置，健康检查正常 |
| E-02 | 通过 | 规划接口可返回任务列表与播报文案 |
| E-03 | 通过 | 说明书场景可完成拍照并语音播报 |
| E-04 | 通过 | 端侧 MobileNetV2 可参与粗分类；细描述依赖云端时延略高 |
| E-05 | 通过 | 药品结构化信息可展示并朗读 |
| E-06 | 通过 | 问答路径可用 |
| E-07 | 通过 | 错误地址下有失败反馈，符合 TTS 兜底要求 |
| E-08 | 通过 | 权限拒绝后有引导/提示，未出现崩溃 |

**补充观察**：

- 真机后端地址若误写 `localhost`，会稳定复现「网络失败」，属配置问题而非功能缺陷。  
- 云端视觉调用通常需数秒，期间状态条进入「思考中」，体验可接受。  
- 模拟器不具备 NPU，端侧分类性能不宜与真机直接对比。

---

## 五、分析与讨论

1. **端云分工合理**：高频、可离线的粗分类放在端侧，意图规划与 Key 托管放在后端，兼顾延迟与合规。  
2. **VUI 闭环完整**：从 ASR/文本到规划或识别，再到 TTS，失败路径也有语音，符合视障场景需求。  
3. **边界需知情**：OCR / 端侧视觉大模型部分能力仍可能为骨架或待补模型，未就绪时应回退云端，验收时不宜一律判失败。  
4. **药品结果免责**：播报仅作辅助理解，实验中亦需强调不能替代医嘱。

---

## 六、实验结论

在后端健康、端侧签名与权限、后端 URL 配置正确的前提下，光语助手能够完成阅读、认物、看药、问答等核心实验目标；端云双态与无障碍反馈机制达到本次实验的预期。后续建议在更多真机与弱网条件下补充延迟与准确率的量化统计。
